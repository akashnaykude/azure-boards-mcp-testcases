Passive Collection — App User Journey (Step 1 → Step 12)

Ticket #214774 · Screens shown in the order the user actually experiences them, top → bottom.

Journey at a glance

  1. Step 1 — First launch, no mailboxes linked (Empty home)
  2. Step 2 — User taps "Link an email" → Provider Picker
  3. Step 3 — Enter email address → validated with backend
  4. Step 4 — On-device IMAP authentication (app password / OAuth)
  5. Step 5 — Home refreshed — new account shown as Connected
  6. Step 6 — Auto scan starts → Scanned emails list
  7. Step 7 — User Selects / Declines → background upload chip appears
  8. Step 8 — Second phone: "Also connect on this device?" prompt
  9. Step 9 — Days later: app-password revoked → Reconnect banner
  10. Step 10 — Trying to link an email that's already owned by someone else (error state)
  11. Step 11 — User taps Disconnect → scope choice (this phone vs everywhere)
  12. Step 12 — Server-driven cleanup (account deletion / dropout)

STEP 4

On-device IMAP authentication Credentials stay local

User creates a Gmail app password (or does OAuth on Outlook) and pastes it into the app. Nothing is sent to Shoppix backend — the password is stored in Android Keystore / iOS Keychain.

  • On success → POST /user/email-accounts with emailAddress + emailProvider.
  • On later failure (revoked app-password) → POST /:id/connection-failure.

STEP 6

Scanned emails — Select or Decline User consent

App searched the mailbox from scrapeFromDateTime, matched against global inbox-filters, sent metadata in bulk, and now shows the user what was found.

  • Checkbox → Selected. Decline link → Declined (terminal — no undo).
  • Hidden scanId per row is the durable handle for later PUT.
  • Paginated at 50 rows per page (max 200).

STEP 7

Background upload runs Non-blocking

User continues using the app. A small dark chip at the bottom shows uploader progress. Each PUT is idempotent (blob keyed by scanId) so retries are safe. On success the backend writes an Outbox row → passivesubmission queue → Receipt service.

  • PATCH decisions batch: PATCH /:id/scans.
  • Each Selected row: PUT /:id/scans/{scanId} with raw MIME.

STEP 9

Reconnect prompt ConnectionFailed only

User revoked the Gmail app password. Next mailbox call fails on-device → app POSTs /:id/connection-failure. Home now shows a red banner. Voluntary disconnects do not show this — only ConnectionFailed.

  • User's earlier Selected rows stay Selected on the server, so uploads resume automatically after reconnect.
  • Reconnect reuses POST /user/email-accounts → transitions ConnectionFailed → Connected.
POST /:id/connection-failure → 204

↓USER TRIES ANOTHER FAILURE CASE
STEP 10

Failure — email is owned by another user Blocked at /validate

User tries to link an address that is already active under a different Shoppix account. The filtered unique index on EmailAddress WHERE IsDeleted = 0 makes this a hard block.

  • Inline error is friendly (no info leak about the other user).
  • Same UX pattern reused for INVALID_EMAIL_ADDRESS. For EMAIL_ALREADY_CONNECTED_ON_DEVICE the app skips forward to the scanned list.
POST /validate → 400 EMAIL_IN_USE

↓USER DECIDES TO DISCONNECT
STEP 11

Disconnect — choose the scope Device only vs everywhere

User taps overflow → Disconnect. A bottom sheet gives two radio options: quiet local disconnect (scope=device) vs full anonymisation (scope=all).

  • Device only — this phone stops scanning; other phones continue.
  • Everywhere & delete — email anonymised, scan logs deleted, blobs removed. Terminal.
DELETE /:id?scope=device | scope=all → 204

↓OR SERVER-DRIVEN CLEANUP
STEP 12

Server-driven cleanup Account deletion / dropout

Profile side publishes useraccountstatusupdated for actionable statuses (Deleted, DroppedOut, Fraudulent, AccountDisabledByUser). The extended AccountStatusFunction anonymises all mailboxes, deletes scan logs and the blob container.

  • Next app call returns 404 EMAIL_ACCOUNT_NOT_FOUND.
  • App silently purges local cache and shows the empty state again.
GET/POST/PATCH/PUT/DELETE → 404 EMAIL_ACCOUNT_NOT_FOUND
